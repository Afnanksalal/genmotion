# Gesture recording

Implemented in 2.4.0. See the [milestone QA report](MILESTONE-QA-2026-09-07.md) for tested paths and remaining acceptance limits.

Studio's layer inspector offers **Record motion** for scene layers. The recorder captures the pointer in canvas coordinates with monotonic timestamps, including stationary samples, for up to the remaining layer interval or 60 seconds. The drawn point represents the layer origin. The current Studio recorder requires an unparented layer; SDK samples are translation offsets in the layer's parent coordinate space. Studio subtracts the layer layout x/y from pointer coordinates before emitting transform tracks; layout positions are not copied into translation offsets.

Before acceptance, the recorder asks the shared compiler for reduced points and renders three native proposed frames. The preview endpoint applies semantic edits to an in-memory document, validates it and renders without saving. It checks the source revision both before and after rendering. Changing recording controls invalidates the prior preview. Acceptance applies one `gesture-record` semantic operation and creates one undo step.

Each recording stores its original samples, origin (`user` or `agent`), start offset, smoothing and reduction settings, source hash and owned track IDs. Start and sample times are seconds in the layer-local timeline. The compiler emits paired linear replacement tracks for `transform.x` and `transform.y`. It retains the original first and last points. Optional smoothing averages samples within a time window; reduction measures interpolation error at each timestamp, preserving pauses and speed changes that spatial-only simplification could discard. The tolerance is measured against smoothed samples, not against unobserved motion between input samples.

The input contract permits 2–10000 strictly ordered samples, up to one hour of recorded time and coordinates within ±1 billion parent-space units. Reduction is limited to one million error comparisons. If that budget is reached, the compiler retains all smoothed samples instead of weakening the error bound. Start times that lose sample timing to floating-point precision are rejected. A layer can retain up to 64 recording provenance entries.

An existing translation track must be explicitly named in `replaceTrackIds` before a recording can replace it. Reusing an existing recording ID targets that recording's owned tracks. Locked tracks still require a separate unlock edit. Motion recipes, constraints, path following, position property links, parameter-bound tracks and active solo states must be resolved explicitly before translation recording. Other tracks are retained. Subsequent explicit track edits can diverge from the recorded source; the provenance retains the original recording rather than pretending that it was recaptured.

SDK exports: `gestureRecordingSchema`, `compileGestureRecording`. Editing-session query: `gesture-preview`. Semantic operation: `gesture-record`. These schemas also flow through CLI and MCP semantic editing. Studio's `/api/edit-preview` accepts a revision, semantic edits, one to three frame times and an optional maximum edge size (128–1280 pixels). It serializes proposed previews per Studio instance and returns PNGs, hashes, source/proposed revisions and validation findings. Returned frame hashes describe the proposed source; they are not silently promoted into evidence for a later saved revision.

The inspector lists retained source trajectories. **Rework** reloads original samples and settings for a new smoothing/reduction preview, preserving the recording identity. Drawing again replaces that recording only after preview and acceptance. **Remove recording and its tracks** targets its owned track IDs and provenance in one reversible transaction; locked tracks still refuse removal.
